# PART A — STRATEGY & ARCHITECTURE (from the handoff)

## A.1 Executive summary and locked thesis
M9R is **not** another multi-agent OS, room, orchestrator, social network, or marketplace. It is a **provider-neutral Session Fabric** that connects actual running humans and agent sessions across tools, providers, machines, and organizations.

> **M9R does not own the intelligence. M9R owns the connection between intelligences.**

- Do not replace the runtime; connect it. Claude Code stays Claude Code; Codex stays Codex; OpenCode stays OpenCode; a teammate's agent stays under that teammate.
- M9R supplies identity, presence, messaging, calls, bounded context transfer, permissions, control, receipts, network relationships, and eventually reputation/economics.
- **You should not need to open M9R to use M9R.** The unit of multiplayer is the live session/runtime endpoint. The web app is the observatory, not the cage.
- Authority lives in deterministic capability/policy enforcement outside the model.
- Never claim "same native session" when a provider only permits resume or a consultation copy.
- Stage 0 reliability + Cloudflare come first; the network spec gates new Session Fabric code.

**Single sentence to preserve:** M9R should make actual live intelligences reachable to each other — across providers, people, machines, and organizations — without forcing them into a new runtime or workspace, while M9R supplies the identity, context, authority, control, trust, and evidence that make that connection safe and useful.

## A.2 Current product reality
M9R already is a multiplayer coordination layer for AI coding agents and human teams: agent connections (Claude Code, Codex, OpenCode, more), human↔agent and agent↔agent messaging, handoff/delegation, authorized human control of connected agents, shared workspace context and memory, presence, permissions, controlled runs, review/evidence/history, terminal/PTY, IDE/diff, team invites and mentions, plus Mission Relay, Mission Worker, Mission Bridge, the web app, and Supabase. Do **not** regress to a generic "parallel task runner" framing.

## A.5 System architecture: M9R Node + Session Fabric
A local/background **M9R Node** bridges native local sessions and the cloud fabric, and keeps running when the UI closes (Windows service/tray, macOS LaunchAgent, Linux systemd --user). Node: discover adapters/sessions, provider bindings, local policy enforcement, PTY ownership, presence, repo/resource access, notifications, reconnect queue, encrypted outbound connection. Cloud: identity/address registry, routing, presence aggregation, trust/contact policy, call coordination, grant/receipt metadata, durable history, web/mobile observability. A local endpoint is offline when its machine is offline — report that truthfully.

## A.6 Provider adapters
- **Codex (first native adapter):** App Server is a long-lived bidirectional JSON-RPC/JSONL harness. M9R is a client: pin/test versions, map thread IDs to endpoint IDs, translate progress/diff/approval events, preserve OpenAI sign-in/model config.
- **Claude:** Agent SDK sessions persistent/resumable; Managed Agents supports attach/follow/send/interrupt/approve. An arbitrary user-launched `claude` terminal may only be observable/resumable — advertise the real fidelity.
- **OpenCode:** prefer the richest stable session API; ACP as interop; pin versions.
- **ACP:** generic first-class adapter (create/resume/prompt/cancel/close, updates, permissions), preserving provider extensions.
- **A2A:** internet-facing interop (Agent Cards, tasks, streaming, push) — use it rather than reinvent.
- **MCP:** tool/resource substrate inside M9R, not the whole multiplayer model; keep session/presence/call semantics explicit application state.

## A.7 Fidelity levels
`LIVE_NATIVE` (supported live interface: send now, stream, cancel, approvals, maybe steer/takeover) · `RESUMABLE_NATIVE` (maps to the real provider session and can resume, cannot inject into the active turn) · `CONSULTATION` (separate helper, labeled honestly). Every adapter publishes a capability matrix: detect live session, live injection, native resume, stream output, receive input, join call, observe, steer, takeover, context sync, permission request/approval, cancellation, transcript access.

## A.8 Core primitives
- **Endpoint** = network identity for a human or an actual running agent session (`id, ownerId, organizationId, type, provider, runtime, nodeId, nativeSessionId, presence, currentWork, capabilities, permissions, interruptible, acceptingCalls, lastSeenAt`). Addresses like `@ayaan/codex-auth`. Provider identity ≠ endpoint identity.
- **Presence** = machine-readable operational state (idle/working/waiting/blocked, current task/repo/scope, interruptibility, accepting calls, commitments), expiring. Durable latest in Supabase; hot fan-out in the Relay.
- **Roomless direct message:** resolve endpoint → policy check → owner's Node → native session method → stream back → record delivery state (accepted → delivered-to-node → delivered-to-session → processing → completed/failed). Offline policy: queue, expire, redirect, or require approval.
- **Machine Call:** temporary live relationship among independently running intelligences; each keeps its own context/model/tools; M9R coordinates events, bounded context, permissions, membership. Lifecycle: caller selects endpoint+goal → policy check → Context Capsule + capabilities requested → owner approval → callee joins at the highest honest fidelity → participants exchange → join/leave → grants revoked at end → durable receipt.

## A.9 Capsules, grants, control, receipts
- **Context Capsule:** bounded, versioned, immutable package (goal/acceptance criteria, relevant files/diff, decisions with provenance, failed approaches, requested permissions, version hashes, explicit exclusions of secrets/unrelated files/prod credentials). Never send whole transcripts/repos by default.
- **Capability Grant:** short-lived signed token bound to subject, resource, actions, call/session, expiry, issuer; verified by the local Node before privileged operations. High-risk actions (deploys, secrets, billing, destructive DB) also need online policy and/or human confirmation.
- **Control:** OBSERVE, STEER, PAUSE, TAKE_CONTROL, RETURN_CONTROL, CANCEL. One mutating controller at a time; many observers. Cross-owner control never silently changes ownership.
- **Work Receipt:** durable evidence from append-only events — participants, task, capsule version, grants/revocations, actions, files/tests/evidence, control transfers, result (accepted/revised/rejected/disputed), cost, commit ids. No blockchain required.

## A.10 Memory, project state, intents, Jev
- Memory becomes typed/versioned project state (id, value, version, source, evidence, supersedes); conflicting assertions surface as contradictions. Embeddings find candidates but are not the truth model.
- Project/world graph: TASK → DECISION → SYMBOL → FILE → TEST → DEPLOYMENT, linked to AGENT/CALL/RECEIPT.
- Intent/collision detection (later): agents publish intended mutations; M9R warns/waits/coordinates/hands off.
- **Jev** is the fast reflex layer for narrow high-volume choices (participant relevance, interruption likelihood, context selection, duplicate/overlap, routing/escalation). It is never the security authority — hard permissions stay deterministic. See B.5.

## A.11 Ambient surfaces

## A.12 Cross-user/org network, marketplace, reputation

Social layer = useful address book (People, Agents, Orgs, capabilities, availability; MESSAGE/CALL/DELEGATE/INVITE/HIRE) — not feeds or likes. ## A.13 Moat, positioning, anti-positioning

- **Say:** "Your agents stay where they are. M9R makes them present everywhere." · "Everyone is building rooms for agents. We're building what connects them outside the room." · "You shouldn't need to open M9R to use M9R."

## A.17 Security, reliability, privacy invariants
No secrets in logs/chat/docs/receipts; rotate anything printed. Provider credentials stay with the provider runtime. Cross-owner access needs explicit capability authority; grants scoped/expiring/revocable/bound. Dangerous actions need deterministic policy and often a human. One mutating controller per session/PTY. Message/event processing idempotent; reconnect must not duplicate dispatch or loop. Presence expires. Adapters publish fidelity; unsupported operations fail explicitly. No fake provider semantics. Containers supervised and observable ("deployed" ≠ "recoverable"). No duplicate production Worker/Bridge consumers. Ephemeral disk reconstructable. Provider auth proven in fresh runtimes. Every backend capability promised to an agent must have a registered agent-facing tool.
