# OathLock v5.1 Production Smoke Test

Run this after deploying the app and applying `supabase-workspace-rules.sql` in the Supabase SQL editor.

## Migration readiness

- [ ] Confirm `workspace_rules` exists in Supabase.
- [ ] Confirm RLS is enabled on `workspace_rules`.
- [ ] Confirm authenticated users can only read and write rules for owned workspaces.
- [ ] Confirm `service_role` access still works for server-side maintenance paths.
- [ ] Confirm indexes exist for `workspace_id`, `(workspace_id, status)`, and `(workspace_id, rule_type)`.
- [ ] Confirm `trg_workspace_rules_updated_at` is installed.
- [ ] Confirm `/dashboard/workspace-rules` shows a migration-required message before the migration, not a crash.

## Full v5.1 loop

- [ ] Open homepage.
- [ ] Click **Analyze agent session**.
- [ ] Paste or upload a representative Claude/Cursor session.
- [ ] Generate Blackbox Report.
- [ ] Confirm 3+ specific rules are generated.
- [ ] Promote selected rules to workspace.
- [ ] Open Workspace Rules page.
- [ ] Confirm promoted rules persist after refresh.
- [ ] Retire one rule.
- [ ] Export AGENTS.md and confirm retired rule is excluded.
- [ ] Export CLAUDE.md.
- [ ] Export Cursor rule.
- [ ] Run compare follow-up session.
- [ ] Mark related rule as helped / needs review / retired.
- [ ] Confirm conservative language only.
- [ ] Confirm no banned legacy language appears.
- [ ] Confirm unauthenticated users are gated from persistence actions.

## Expected production posture

OathLock recommends carrying only active workspace rules into future agent runs.
Needs-review and retired rules stay visible for curation, but retired rules are excluded from exports.
